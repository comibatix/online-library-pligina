# Использование искусственного интеллекта при разработке

В ходе выполнения тестового задания активно использовались инструменты на базе искусственного интеллекта (Large Language Models) в качестве ассистента разработчика. 

ИИ не заменял процесс принятия архитектурных и логических решений, а выступал в роли "парного программиста" (pair programmer) для ускорения рутинных задач.

## Этапы использования ИИ

### 1. Архитектура и проектирование
- Обсуждение структуры трёхслойной архитектуры (Controllers / Services / Repositories) для соблюдения принципа Separation of Concerns.
- Проектирование схемы базы данных и составных уникальных ключей для предотвращения дублирования лайков и записей в списке чтения.

### 2. Написание кода (Boilerplate & Logic)
- Генерация шаблонного кода для CRUD-операций в слоях Repository и Controller.
- Написание регулярных выражений для валидации данных (например, формат OLID).
- Создание конфигурационных файлов (`.eslintrc.json`, `.prettierrc`, `vitest.config.mts`).

### 3. Отладка и рефакторинг
- Анализ ошибок TypeScript и трассировок стека (stack traces) при миграции кода в новую архитектуру.
- Оптимизация импортов и исправление путей после реорганизации папок.

### 4. Тестирование
- Генерация наборов тестовых данных (валидные и невалидные OLID, email, статусы).
- Написание unit-тестов для проверки логики throttling и валидации с использованием фреймворка Vitest.

### 5. Документация
- Формирование структуры и наполнение файлов `README.md` (корневой, backend, frontend).
- Генерация спецификации OpenAPI 3.0 (Swagger) для всех endpoint'ов.
- Написание данного отчёта об использовании ИИ.

## Контроль качества

Весь сгенерированный ИИ код подвергался строгому ручному контролю:
1. **Понимание кода:** Каждая строка была прочитана, осмыслена и при необходимости адаптирована под конкретные требования задания.
2. **Безопасность:** Ручная проверка отсутствия хардкода секретных ключей и корректности использования middleware авторизации.
3. **Тестирование:** Весь функционал был вручную протестирован через UI и Swagger, а критические участки покрыты автоматическими тестами.

## Заключение

Использование ИИ позволило сократить время на написание шаблонного кода и документации примерно на 40%, сфокусировав основное время разработчика на проектировании архитектуры, реализации сложных механик (кеширование, throttling) и обеспечении качества продукта.
